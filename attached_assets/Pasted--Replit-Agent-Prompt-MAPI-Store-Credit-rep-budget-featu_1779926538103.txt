### 1. Business context (this is new, you don't know it yet)

**Système D** is a 3PL company (warehousing, picking, packing, shipping). I'm building this Replit app as their custom client portal — clients log in, manage orders, view inventory, request services.

**MAPI** is one of Système D's clients. MAPI does NOT run a normal e-commerce business. Instead, they have **20 sales representatives** ("reps") in the field. Each rep needs to send physical product samples to their own clients (architects, designers, end customers) so those clients can see/touch the samples before placing a real wholesale order.

MAPI runs a private Shopify store (`tnt5ar-ki.myshopify.com`) that acts as a **sample-ordering catalog**. The Shopify store is NOT public — only the 20 reps have customer accounts on it. The catalog has a few hundred sample products (tile, flooring, etc.). Each product has a price like `$8.50` — but **this is not a real price**, it's a synthetic value MAPI uses to ration how many samples each rep can request per month.

**The budget pattern:**
- Each rep is given a monthly "sample budget" (e.g. $500 CAD/month).
- Reps shop the Shopify store with their budget. Each "purchase" deducts from their budget. When they hit zero, they can't order more until next month's top-up.
- No real money changes hands. The synthetic prices are just a rationing mechanism.
- Système D's warehouse team receives the rep's "order" from Shopify, picks/packs the samples, and ships them to the rep's end client.

**Who manages this:** MAPI managers log into the **Système D** platform (this app), NOT the Shopify admin. They never need to touch Shopify directly. Système D is the hub; Shopify runs in the background.

What MAPI managers need to do in Système D:
1. Add a new rep (creates a Shopify Customer behind the scenes)
2. Set / view / top up that rep's monthly budget
3. See every rep's current balance in one list
4. See per-rep transaction history (credits + debits + expirations)
5. Manually adjust a balance (give a bonus, claw back funds, etc.)
6. Deactivate a rep (final debit to zero, optionally delete the Customer in Shopify)

### 2. Architecture decision (important — read carefully)

I originally thought we'd use **Shopify Gift Cards** for this. **We are NOT using gift cards.** Reason: Shopify's Gift Card Admin API does not support topping up the balance of an existing gift card. The `giftCardUpdate` mutation can only change `customerId`, `expiresOn`, `note`, `recipientAttributes`, `templateSuffix` — there is no `giftCardCredit` mutation. This is a hard limit of the API.

**We are using Shopify Store Credit Accounts instead.** Store Credit is Shopify's purpose-built primitive for this exact pattern:

| Feature | Gift Cards | Store Credit |
|---|---|---|
| Top-up balance | ❌ Impossible | ✅ `storeCreditAccountCredit` |
| Manual debit | ❌ | ✅ `storeCreditAccountDebit` |
| Per-customer (no codes) | Code-based | Customer-bound |
| Auto-applies at checkout | Type code | Auto if logged in |
| Per-credit expiration | Whole card | Per credit transaction |
| Auto-create account | n/a | Yes, on first credit |

**One important constraint:** Store Credit only applies at checkout when the rep is authenticated via Shopify's **new customer accounts** auth (the email-code login). I will ensure this is enabled on the Shopify side — you do not need to handle storefront auth.

#### 4.2 Database schema (Système D's Postgres / whatever DB the app uses)

Add a `mapi_reps` table that mirrors the Shopify Customer + caches their current state for fast dashboard reads:

```sql
CREATE TABLE mapi_reps (
  id                       UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shopify_customer_gid     TEXT UNIQUE NOT NULL,    -- "gid://shopify/Customer/123..."
  email                    TEXT NOT NULL,
  first_name               TEXT,
  last_name                TEXT,
  status                   TEXT NOT NULL DEFAULT 'active', -- 'active' | 'archived'
  monthly_budget_amount    NUMERIC,                  -- default budget (e.g. 500)
  monthly_budget_currency  TEXT DEFAULT 'CAD',
  current_balance          NUMERIC,                  -- cached from Shopify
  current_balance_currency TEXT,
  last_balance_refresh_at  TIMESTAMPTZ,
  created_at               TIMESTAMPTZ DEFAULT NOW(),
  updated_at               TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_mapi_reps_status ON mapi_reps(status);

CREATE TABLE mapi_rep_credit_log (
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  rep_id                UUID REFERENCES mapi_reps(id),
  shopify_customer_gid  TEXT NOT NULL,
  action                TEXT NOT NULL,              -- 'credit' | 'debit' | 'monthly_renewal'
  amount                NUMERIC NOT NULL,
  currency              TEXT NOT NULL,
  expires_at            TIMESTAMPTZ,
  reason                TEXT,
  performed_by_user_id  UUID,                       -- the Système D admin who did it
  shopify_transaction_id TEXT,
  created_at            TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_credit_log_rep ON mapi_rep_credit_log(rep_id, created_at DESC);
```

The `current_balance` column is a **cache** — refresh it whenever you credit/debit, and add a background job that re-syncs all reps' balances every 15 minutes from Shopify (in case checkout debits happened on Shopify directly).

#### Read a rep's balance and history (used in `getRepBalance`, `getRepTransactionHistory`)

```graphql
query repDetail($customerId: ID!) {
  customer(id: $customerId) {
    id email firstName lastName tags
    storeCreditAccounts(first: 5) {
      edges {
        node {
          id
          balance { amount currencyCode }
          transactions(first: 100, reverse: true, sortKey: CREATED_AT) {
            edges {
              node {
                __typename
                ... on StoreCreditAccountCreditTransaction {
                  amount { amount currencyCode }
                  createdAt
                  expiresAt
                }
                ... on StoreCreditAccountDebitTransaction {
                  amount { amount currencyCode }
                  createdAt
                }
                ... on StoreCreditAccountExpirationTransaction {
                  amount { amount currencyCode }
                  createdAt
                }
                ... on StoreCreditAccountDebitRevertTransaction {
                  amount { amount currencyCode }
                  createdAt
                }
              }
            }
          }
        }
      }
    }
  }
}
```

### 6. Error handling — non-negotiable

For every Shopify mutation:
1. Check HTTP status. Non-2xx → throw with status + body.
2. Parse `errors` array (GraphQL-level errors). Non-empty → throw.
3. Parse `userErrors` array on the payload. Non-empty → throw with the human message.

Known business-logic errors to handle explicitly with friendly UI messages:
- `"A positive amount must be used to credit a store credit account"` → user UI: "Amount must be greater than zero."
- `"The operation would cause the account's credit limit to be exceeded"` → user UI: "Maximum balance reached for this rep. Cap the credit or contact support."
- Insufficient balance on debit → user UI: "Cannot debit more than current balance ($X.XX)."
- Customer not found → user UI: "Rep not found in Shopify — record may be stale, refresh page."

Wrap the token exchange in a retry-once-on-401 (in case the token was just revoked by a rotation). Don't infinite-loop.
