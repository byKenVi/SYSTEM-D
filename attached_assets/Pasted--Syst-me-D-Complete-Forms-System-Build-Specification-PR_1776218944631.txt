# Système-D — Complete Forms System Build Specification

## PROJECT CONTEXT

We are building a client portal for **Système-D**, a warehousing, sorting (tri), and co-packing company based in Quebec, Canada. The portal allows clients to submit service requests through digital forms, and allows the Système-D internal team to manage operations.

The app has these user types:
- **Client (external)**: submits forms for service requests, views project status (view + questions only)
- **Admin / Système-D team (internal)**: fills forms on behalf of clients, manages projects, modifies submitted forms, tracks time

There are **5 forms** total. Each form must:
1. Auto-generate a unique form number on creation
2. Store all data persistently (database)
3. Be accessible from the CRM (via direct link per client)
4. Generate a PDF version of the completed form
5. Support photo/video uploads where specified
6. Be editable after submission (by team only, not by client)
7. Be bilingual-ready (French primary, English secondary) — all labels in French

## AUTOMATION FLOW (applies to all forms)

When ANY form is submitted:

```
1. FORM SUBMITTED
   ↓
2. AUTO-GENERATE unique form number (prefix + increment)
   ↓
3. STORE in database with:
   - form_id
   - form_type (ENT/TRI/INS/F015/LIV)
   - client_id (linked to CRM account)
   - submitted_by (user ID)
   - submitted_at (timestamp)
   - status: "submitted" | "in_review" | "approved" | "completed"
   - all form field data as JSON or relational tables
   ↓
4. CREATE PROJECT (Zoho Project integration — future)
   - Project name = form type + form number
   - Attach links to form(s)
   - Give client view-only + questions access
   ↓
5. CREATE SERVICE in Zoho Books (future)
   - Product/Service name = project name
   - Create devis (estimate) with project number
   - Add service as line item
   ↓
6. GENERATE PDF of completed form
   - Attach to project
   - Attach to devis email
   ↓
7. SEND EMAIL notification
   - To client: "Your submission has been received"
   - To admin team: "New [form type] submission from [client]"
```

**Special flow for TRI:**
```
Form 2 (TRI) submitted
  ↓
Auto-create Form 3 (Inspection Instructions) — linked by TRI form number
  ↓
Both forms attached to same Zoho Project
  ↓
Both PDFs attached to devis email
```

**Special flow for Co-packing (F015):**
```
Form 4 (F015) submitted
  ↓
Check: does client need shipping?
  ↓ Yes
Auto-trigger Form 5 (Livraison) questions within the form
  ↓
All data attached to same project
```

## UI / UX REQUIREMENTS

### Layout
- **Left sidebar navigation** with menu items per form type
- **Top header** with client name, form number, status badge
- **Main content area** with the form
- **Tab navigation** within Form 4 (F015) for its 5 sub-forms
- Mobile responsive (field workers may use tablets)

### Form behavior
- **Auto-save** as draft every 30 seconds (or on field blur)
- **Save as draft** button — form can be partially filled and resumed
- **Submit** button — validates all required fields, changes status to "submitted"
- **Conditional fields**: use show/hide logic (not separate pages) — fields appear/disappear based on selections
- **Repeating sections**: "Add row" / "Add item" buttons. Each added item gets a remove (X) button. Items are draggable for reordering where it makes sense.

### File uploads
- Accept: JPG, PNG, HEIC, PDF, MP4, MOV
- Max file size: 25MB per file
- Show thumbnail preview after upload
- For Loom videos: accept URL paste, show embedded preview
- Store files with reference to form_id + field_id

### Auto-calculations
- All "Total heure" fields = `Fin - Début` (in hours, 2 decimal places)
- When "Nb gens" is present: `Total heure = (Fin - Début) × Nb gens`
- Section totals = SUM of all row totals in that section
- RENDEMENT in Express Global = total quantity / total hours

### PDF generation
- Generate clean, professional PDF matching the original Excel/Word layouts
- Include all uploaded images inline
- Include form header with: company logo, form number, date, client name
- Include footer with: revision number, page numbers

### Permissions
- **Client**: can create new forms, edit own drafts, submit, view submitted (read-only after submit)
- **Admin**: can create forms for any client, edit any form at any stage, change status, view all forms
- **Team member**: can edit forms assigned to their projects, log time entries

### Data model considerations
- Each form type should have its own database table (or collection)
- Repeating sections (NC items, time tracking rows, criteria items) should be stored as arrays/sub-tables
- File uploads stored with references (URLs/paths), not inline
- Form revisions tracked: every save creates a version snapshot
- Linked forms (TRI → Inspection) maintain foreign key relationships

## TECH STACK NOTES

- Build each form as a reusable component
- Use a form builder pattern: field definitions drive rendering (makes it easier to add/modify fields later without rewriting components)
- All date/time fields should use ISO format internally, display in `DD/MM/YYYY` and `HH:MM` (24h) format
- Currency in CAD ($) unless specified otherwise
- All text labels in French as specified above
- Support dark/light mode
- API endpoints for each form: `GET /forms/{type}`, `POST /forms/{type}`, `PUT /forms/{type}/{id}`, `GET /forms/{type}/{id}/pdf`

---

## PRIORITY ORDER FOR BUILDING

1. **Form 2 (TRI)** + **Form 3 (Inspection Instructions)** — these are the most urgent, used daily, and the TRI→Inspection link is the most complex flow
2. **Form 4 (F015 Co-packing)** — 5 tabs, heavy time tracking, used by internal team
3. **Form 1 (Entreposage)** — standard storage form with conditional logic
4. **Form 5 (Livraison)** — simplest standalone form, also reused as sub-form
5. **Automation flows** (PDF generation, email notifications, status management)
