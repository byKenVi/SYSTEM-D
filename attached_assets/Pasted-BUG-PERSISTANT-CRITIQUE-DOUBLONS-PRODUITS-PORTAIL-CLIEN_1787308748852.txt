BUG PERSISTANT CRITIQUE — DOUBLONS PRODUITS PORTAIL CLIENT MAPEl — À CORRIGER DÉFINITIVEMENT

Contexte :
Cela fait plusieurs tentatives que le problème de doublons produits est supposé corrigé, mais il est toujours visible dans l’interface client réelle.

Capture QA actuelle :
Dans le portail client Mapei, onglet “Mes Produits”, le compteur affiche encore :

396 produits

Alors que le catalogue attendu est :

198 produits uniques

Les lignes visibles sont clairement dupliquées :
- même image ;
- même nom ;
- même SKU ;
- même prix ;
- même statut stock ;
- même produit affiché deux fois.

Exemples visibles :
- “Boîte pouvant contenir 20 morceaux (9106)” SKU MK10 apparaît deux fois.
- “Boîte pouvant contenir 8 morceaux (9107)” SKU MK11 apparaît deux fois.

Les corrections précédentes ont prétendu :
- dédoublonnage serveur ;
- dédoublonnage client ;
- dédoublonnage admin ;
- cache no-store ;
- tests passés ;
- compteur corrigé.

Mais en QA réelle, ce n’est toujours PAS corrigé.

Objectif :
Corriger définitivement le problème, en prouvant que la route réellement utilisée par l’interface client retourne 198 produits uniques, pas 396.

Ne fais pas un simple filtre supplémentaire sans diagnostic.
Ne réponds pas seulement “tests passés”.
Ne suppose pas que la bonne route est corrigée.
Ne termine pas tant que tu n’as pas prouvé la réponse réelle utilisée par l’écran.

==================================================

La correction doit être appliquée à la source réellement utilisée.

B. Backend route admin / view-as

D. Frontend

- invalidation React Query correcte ;

- après refresh, 198 doit apparaître.

==================================================
5. RÈGLE DE DÉDOUBLONNAGE EXACTE
==================================================

Un produit ne doit s’afficher qu’une seule fois pour un même compte client si l’une de ces clés est identique :

Priorité 1 :
- `zohoItemId` identique et non null.

Priorité 2 :
- `shopifyVariantId` identique et non null.

Priorité 3 :
- `shopifyProductId` identique et SKU identique.

Priorité 4 :
- boutique normalisée + SKU identique + nom normalisé + prix identique.

Ne pas fusionner deux produits différents uniquement parce que leurs noms se ressemblent.

Pour chaque groupe de doublons, conserver en priorité :
1. produit rattaché au contact connecté ;
2. sinon produit rattaché au contact principal de l’intégration active ;
3. sinon produit le plus récemment synchronisé ;
4. sinon plus petit id stable.

La règle doit être déterministe.

6. NETTOYAGE BASE — SI NÉCESSAIRE
==================================================

Si le diagnostic montre que les doublons sont réellement stockés en base et que le simple dédoublonnage de lecture reste fragile, proposer un nettoyage sûr.

Mais attention :
Ne supprime pas de données tant que le diagnostic n’a pas prouvé que ce sont des doublons exacts.

Nettoyage accepté uniquement si :
- même compte client ;
- même boutique ;
- même SKU ;
- même Shopify variant ou même Zoho item ;
- mêmes données principales ;
- aucune commande/historique ne dépend directement de la ligne supprimée.

Si suppression risquée :
- ne pas supprimer ;
- créer un champ ou une logique de consolidation ;
- marquer les doublons comme hidden/duplicate si le schéma le permet ;
- sinon dédoublonnage lecture obligatoire.

Si nettoyage fait :
- sauvegarder la liste des ids concernés dans un log ou rapport ;
- ne jamais supprimer des produits d’un autre client ;
- ne jamais supprimer produits SystemD ;
- ne jamais supprimer commandes/historiques.
