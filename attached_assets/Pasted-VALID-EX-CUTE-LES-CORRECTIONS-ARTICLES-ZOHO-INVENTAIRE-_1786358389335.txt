==================================================
LOT 2 — NE PLUS CRÉER UN ARTICLE ZOHO PAR SOUMISSION
==================================================

Problème actuel :
createFormSalesOrder() crée toujours un nouvel item Zoho via POST /items avec le nom :
{formNumber} - {formType}

Exemples :
- ENT-006 - Entreposage
- F015-006 - Co-packing
- INS-001 - Inspection

Ce comportement ne doit pas continuer en production.

Correction attendue :
Remplacer la création d’un article unique par soumission par une logique de réutilisation d’articles/services génériques.

Articles génériques à utiliser :
- Service - Entreposage
- Service - Co-packing
- Service - Inspection
- Service - Livraison
- Service - Tri

Nouvelle logique dans createFormSalesOrder() :

1. Déterminer l’article générique selon formType.
2. Chercher dans Zoho Inventory si cet article générique existe déjà.
3. Si l’article existe :
   - réutiliser son item_id.
4. Si l’article n’existe pas :
   - le créer une seule fois dans Zoho Inventory comme service sales.
5. Créer le Sales Order avec cet item générique.
6. Mettre les détails spécifiques de la soumission dans :
   - description de ligne ;
   - notes du Sales Order ;
   - référence ;
   - numéro de soumission ;
   - nom du client ;
   - détails utiles du formulaire.

Important :
Le nom de l’article Zoho ne doit plus être ENT-006 / F015-006 / INS-001.
Le numéro de soumission doit être dans la description ou les notes, pas dans le nom d’un nouvel article.

LOT 3 — DÉDUPLICATION / RETRY
==================================================

Corrige aussi le risque de doublon.

Si un Sales Order Zoho existe déjà pour une soumission :
