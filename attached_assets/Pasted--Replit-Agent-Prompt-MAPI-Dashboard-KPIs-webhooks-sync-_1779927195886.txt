### 2. Architecture decision (important — read carefully)

**We are using webhooks + a local mirror of Shopify data**, NOT live GraphQL queries on every dashboard page load. Reasoning:

| Approach | Why we're not using it |
|---|---|
| Live GraphQL on each page load | Slow (multi-second dashboards), eats rate limit, breaks if Shopify is down |
| Periodic polling (cron every 15min) | Wasteful re-pulls, 15-min staleness, no event audit trail |
| ShopifyQL Reports API | Requires `read_reports` scope (not in our current token); 12h data lag |
| **Webhooks + local mirror** ✅ | Near-realtime, low rate-limit cost, audit trail, dashboard reads from local DB (fast) |

**The pattern:**
1. On integration setup: subscribe to a fixed set of Shopify webhook topics.
2. On every webhook delivery: verify HMAC signature, upsert into local mirror tables, recompute affected KPI rows.
3. On initial setup (one time): backfill last 90 days of orders/customers/inventory via GraphQL pagination.
4. Nightly: a reconciliation job re-queries the last 25 hours and upserts everything, so any webhook delivery failures get caught.

The dashboard reads from local mirror tables + a `mapi_rep_kpis` cache table. **No Shopify call happens on dashboard page load.**

#### 4.2 Webhook receiver — `routes/webhooks/shopify/*.ts`

Mount under `/webhooks/shopify/*`. **Critical security requirements:**

1. **Capture the raw request body before any JSON parsing.** Shopify computes HMAC over the raw bytes; if your framework parses the body first, the HMAC check will fail. In Express:
   ```ts
   app.use('/webhooks/shopify', express.raw({ type: 'application/json' }));
   ```
2. **Verify HMAC on every webhook before doing anything else.** Use timing-safe comparison. Reject 401 if it fails.
3. **Return 200 within 5 seconds.** Shopify retries delivery if you take too long. Acknowledge immediately, process async (worker queue, or just `setImmediate`).
4. **Idempotent processing.** Shopify can redeliver the same webhook. Always upsert, never insert.
5. **Always log the raw payload to `shopify_webhook_events`** before processing — gives you a replay log if something goes wrong.

Topics to handle:

| Endpoint | Topic | Action |
|---|---|---|
| `/webhooks/shopify/orders-create` | `ORDERS_CREATE` | Upsert order + line items, update KPI cache for that customer |
| `/webhooks/shopify/orders-updated` | `ORDERS_UPDATED` | Upsert (status changes, total adjustments) |
| `/webhooks/shopify/orders-cancelled` | `ORDERS_CANCELLED` | Set `cancelled_at`, recompute KPIs |
| `/webhooks/shopify/orders-paid` | `ORDERS_PAID` | Update `financial_status` |
| `/webhooks/shopify/customers-create` | `CUSTOMERS_CREATE` | Upsert customer (catches reps created outside Système D) |
| `/webhooks/shopify/customers-update` | `CUSTOMERS_UPDATE` | Upsert customer |
| `/webhooks/shopify/inventory-levels-update` | `INVENTORY_LEVELS_UPDATE` | Upsert inventory level |
| `/webhooks/shopify/products-update` | `PRODUCTS_UPDATE` | Upsert product (titles, status) |

**Reference implementation pattern (Node/Express — adapt to whatever the app uses):**

```ts
import crypto from 'node:crypto';

function verifyHmac(rawBody: Buffer, hmacHeader: string | undefined): boolean {
  if (!hmacHeader) return false;
  const computed = crypto
    .createHmac('sha256', process.env.SHOPIFY_WEBHOOK_SECRET!)
    .update(rawBody)
    .digest('base64');
  try {
    return crypto.timingSafeEqual(Buffer.from(hmacHeader), Buffer.from(computed));
  } catch {
    return false;
  }
}

app.post('/webhooks/shopify/orders-create', async (req, res) => {
  const rawBody = req.body as Buffer;                          // raw, NOT parsed
  const hmac = req.headers['x-shopify-hmac-sha256'] as string;
  const topic = req.headers['x-shopify-topic'] as string;
  const shopDomain = req.headers['x-shopify-shop-domain'] as string;

  const hmacValid = verifyHmac(rawBody, hmac);

  // Log every delivery — even invalid ones (security audit trail)
  const order = hmacValid ? JSON.parse(rawBody.toString('utf8')) : null;
  const eventId = await db.shopifyWebhookEvents.insert({
    topic,
    shopify_resource_id: order?.id ?? null,
    hmac_valid: hmacValid,
    raw_payload: order ?? { invalid: true },
  });

  if (!hmacValid) return res.status(401).send('Invalid signature');

  // ACK fast, process async
  res.status(200).send('OK');

  // Process (run in background — use a queue if you have one)
  setImmediate(async () => {
    try {
      await processOrderCreate(order);
      await db.shopifyWebhookEvents.update({ id: eventId }, { processed_at: new Date() });
    } catch (err) {
      await db.shopifyWebhookEvents.update({ id: eventId }, {
        processed_at: new Date(),
        processing_error: err.message,
      });
      // Don't throw — Shopify already got the 200
    }
  });
});
```

#### 4.3 KPI computation — `lib/mapi/kpis.ts`

After every order webhook (create / updated / cancelled), refresh the KPI cache row for the affected customer. Don't recompute all reps — only the one that changed.

```ts
async function refreshRepKpi(shopifyCustomerId: bigint): Promise<void>
async function refreshAllRepKpis(): Promise<void>          // for the cron + reconciliation
async function refreshTopProducts(): Promise<void>          // monthly aggregation refresh
```

Computation logic (one rep at a time):
```sql
-- For one customer:
WITH agg AS (
  SELECT
    customer_id,
    COUNT(*) FILTER (WHERE shopify_created_at >= date_trunc('month', NOW())) AS orders_this_month,
    COUNT(*) FILTER (WHERE shopify_created_at >= NOW() - INTERVAL '30 days') AS orders_last_30_days,
    COALESCE(SUM(total_price) FILTER (WHERE shopify_created_at >= date_trunc('month', NOW())), 0) AS total_value_this_month,
    COALESCE(SUM(total_price) FILTER (WHERE shopify_created_at >= NOW() - INTERVAL '30 days'), 0) AS total_value_last_30_days,
    MAX(shopify_created_at) AS last_order_at
  FROM shopify_orders
  WHERE customer_id = $1 AND cancelled_at IS NULL
  GROUP BY customer_id
)
INSERT INTO mapi_rep_kpis (shopify_customer_id, ...)
SELECT customer_id, ... FROM agg
ON CONFLICT (shopify_customer_id) DO UPDATE SET ...;
```

The credit balance / utilization fields are pulled from `mapi_reps.current_balance` (the rep budget feature's cache) — no Shopify call needed.

#### 4.5 Initial backfill — `scripts/backfill-shopify.ts`

A one-shot script that pulls the last 90 days of orders + all customers + all products + current inventory levels via paginated GraphQL queries, upserts into the mirror tables, and finally calls `refreshAllRepKpis()` and `refreshTopProducts()`.

Pagination pattern (loop until `hasNextPage: false`):

```graphql
query backfillOrders($cursor: String, $sinceQuery: String!) {
  orders(first: 250, after: $cursor, query: $sinceQuery, sortKey: CREATED_AT) {
    pageInfo { hasNextPage endCursor }
    edges {
      node {
        id legacyResourceId name createdAt updatedAt cancelledAt
        displayFinancialStatus displayFulfillmentStatus
        totalPriceSet { shopMoney { amount currencyCode } }
        subtotalPriceSet { shopMoney { amount currencyCode } }
        totalTaxSet { shopMoney { amount currencyCode } }
        customer { id legacyResourceId email firstName lastName tags }
        lineItems(first: 50) {
          edges {
            node {
              id title variantTitle sku quantity
              originalUnitPriceSet { shopMoney { amount } }
              totalDiscountSet { shopMoney { amount } }
              variant { id legacyResourceId product { id legacyResourceId title handle productType vendor status } }
            }
          }
        }
      }
    }
  }
}
```
Variables: `{"sinceQuery": "created_at:>=2026-03-01", "cursor": null}` then page.

`legacyResourceId` gives the numeric BIGINT ID for the mirror tables. The `id` field is the GraphQL `gid://`.

Throttle: insert a 200ms sleep between pages to stay well under rate limits. For MAPI volume this is plenty.

#### 4.6 Nightly reconciliation — `jobs/shopify-reconcile.ts`

Cron-scheduled job (3am every night). Re-queries the **last 25 hours** of orders/customers/inventory updates and upserts — catches any webhook delivery failures. The 25-hour window has 1h overlap with the previous run for safety.

```ts
async function reconcileShopify(): Promise<{
  ordersScanned: number,
  ordersUpserted: number,
  webhookDriftDetected: number,

```

Use `updated_at:>=<timestamp>` filter in the GraphQL query, not `created_at` — so we also catch order updates (status changes) that webhook handlers may have missed.

After reconciliation, run `refreshAllRepKpis()` and `refreshTopProducts()`.

### 6. Error handling — non-negotiable

**Webhook receiver:**
- Always log to `shopify_webhook_events` BEFORE processing (regardless of HMAC validity).
- HMAC fail → 401, log it, never process.
- Processing error → catch internally, log to `shopify_webhook_events.processing_error`, NEVER re-throw out of the handler (Shopify already got the 200).
- Always upsert, never insert. Use the Shopify ID as the primary key conflict target.

**GraphQL calls (backfill, reconcile, KPI refresh):**
- Check HTTP status, then GraphQL `errors`, then `userErrors`. Throw on any.
- On 429 (rate limited) — read `Retry-After` header (or check `extensions.cost.throttleStatus.restoreRate`), wait, retry once.
- On token expiry (401 mid-batch) — let the cached client auto-refresh and retry the page.

**Reconciliation:**
- Wrap in a try/finally that always logs the outcome (orders scanned, upserts done, errors) to a `shopify_sync_log` table or to your structured logger.
