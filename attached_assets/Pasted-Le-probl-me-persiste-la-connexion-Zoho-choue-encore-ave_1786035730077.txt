Contexte important :
J’ai dû créer une nouvelle application dans Zoho API Console, car je ne voyais pas d’application existante.
Dans une première itération, tu m’as demandé de remplacer seulement ZOHO_CLIENT_SECRET par celui de la nouvelle app.
Mais si ZOHO_CLIENT_ID appartient encore à l’ancienne app, alors le client secret de la nouvelle app ne peut pas fonctionner.

Je veux uniquement corriger et sécuriser la configuration OAuth Zoho.

1. VÉRIFIER LA PAIRE CLIENT ID / CLIENT SECRET
==================================================

Vérifie que ZOHO_CLIENT_ID et ZOHO_CLIENT_SECRET viennent exactement de la même application Zoho API Console.

Ne suppose pas que c’est correct.

Ajoute un diagnostic sécurisé côté logs serveur, sans jamais afficher le secret complet :
- source utilisée pour ZOHO_CLIENT_ID : env ou DB ;
- présence ou absence de ZOHO_CLIENT_ID ;

- 6 premiers et 4 derniers caractères du client ID seulement ;
- ne jamais logger le client secret ;
- détecter les espaces ou retours à la ligne autour des secrets.

Si le code lit encore un ancien client ID depuis admin_settings au lieu de l’environnement, corrige cela.

La source de vérité doit être claire :
- soit uniquement les secrets Replit ;
- soit une priorité explicite secrets Replit > base de données ;
- mais il ne faut jamais mélanger un client ID ancien avec un client secret nouveau.

2. VÉRIFIER LE REDIRECT URI
==================================================

Affiche dans les paramètres Système D le redirect URI exact à enregistrer dans Zoho API Console.

Vérifie que le code utilise exactement ce redirect URI dans le flux OAuth.

Le redirect URI doit correspondre exactement à celui configuré dans Zoho API Console :
- même https ;
- même domaine ;
- même chemin ;
- pas de slash final en trop ;
- pas d’ancien domaine Replit ;
- pas de domaine production si on est en dev.

==================================================

Quand on change de Client ID / Secret, les anciens refresh tokens Zoho ne sont plus valides.

- efface uniquement les anciens tokens Zoho OAuth ;

  - portal ID ;
  - portal name ;
  - last tested at.

==================================================

Un échec OAuth, un invalid_client_secret ou un token refresh échoué ne doit jamais supprimer automatiquement la configuration Zoho Projects.

“Connexion Zoho à renouveler.”

- Zoho Projects portal ID ;
