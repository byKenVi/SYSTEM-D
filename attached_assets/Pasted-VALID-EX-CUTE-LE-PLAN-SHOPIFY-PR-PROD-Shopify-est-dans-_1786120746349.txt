LOT 1 — CORRECTIONS BLOQUANTES SHOPIFY
==================================================

1. Backoff / suspension sur erreurs 401

Problème :
Le scheduler Shopify génère actuellement une erreur 401 toutes les 60 secondes avec un token invalide.
C’est inacceptable en production.

Correction attendue :
- détecter les erreurs Shopify 401 / token invalide ;
- ne pas spammer activity_logs à chaque cycle ;
- après plusieurs erreurs consécutives, suspendre temporairement la sync de cette intégration ;
- afficher clairement dans l’admin que la connexion Shopify est invalide ;
- permettre à l’admin de corriger le token puis retester.

Implémentation possible :
- ajouter un champ syncPausedUntil ou équivalent ;
- ajouter un champ lastSyncError / lastConnectionStatus si nécessaire ;
- ne pas désactiver silencieusement l’intégration sans message admin ;
- ne pas supprimer les produits déjà importés si le token devient invalide.

Important :
Les produits déjà importés doivent rester visibles.
Un token invalide doit bloquer la mise à jour, pas vider le catalogue.

Afficher clairement :

LOT 4 — NOUVEAUX PRODUITS SHOPIFY
==================================================

L’audit indique que l’auto-sync met à jour uniquement les variants déjà importés et ignore les nouveaux produits Shopify.

Analyse puis corrige si possible sans refonte :
- soit l’auto-sync produit doit aussi upsert les nouveaux produits actifs Shopify ;
- soit il faut clairement limiter l’auto-sync aux mises à jour et rendre le bouton “Importer tous les produits Shopify” évident pour ajouter les nouveaux produits.

Ma préférence :
Si le risque est faible, corriger l’auto-sync pour upsert aussi les nouveaux produits actifs.
Si le risque est trop élevé avant prod, ne change pas la logique automatique, mais rends le fonctionnement explicite dans l’interface.

Dans tous les cas, l’admin doit comprendre comment faire apparaître un nouveau produit Shopify dans Système D.
